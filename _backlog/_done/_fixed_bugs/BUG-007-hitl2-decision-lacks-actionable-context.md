# BUG-007: HITL2 决策提示未提供人类可据以选择的上下文

> 严重级别: P0 | 发现: 2026-07-24 | 状态: 活跃

## 症状

独立全假 demo 到达 HITL2 后，要求用户从以下路径中选择：

```text
proceed: 按当前研究计划继续。
revise_view: 回到综合分析并调整当前观点。
repair: 保留当前方向并补充缺失证据。
rerun: 开始新的研究轮次并按新方向检索。
stop: 停止当前研究流程。
```

提示没有说明当前研究判断、缺失的证据、当前计划，或为何某条路径更合适。
用户无法据此做出知情选择，只能猜测、粘贴可见的整行选项，或为了离开提示而
输入 `proceed`。这将本应由智能体完成的分析和路线判断转嫁给用户，阻断了
核心研究工作流；全假模式尤其容易误导，因为没有可检查的发现或报告。

安装入口还存在一个叠加的上手问题：README 命令块包含 shell 行内注释。在未启用
`INTERACTIVE_COMMENTS` 的交互式 zsh 中，`make install # ...` 会将 `#` 作为
Make 目标传入，并报 `No rule to make target '#'.`；已在 `agent/` 中时重复
`cd agent` 也会失败。

## 根因

HITL2 提示契约只有通用标题、目标与有限的路径后果。其 fake 节点故意不产生研究
发现，但 CLI 却把同一条路径菜单渲染成真实决策点。展示层没有区分教学用 fixture
控制与由简报支撑的决策，也没有要求智能体先形成推荐、说明依据并给出默认动作。
`repair`、`rerun` 之类的名称是控制流术语，不是面向用户的决策。

文档假定了 Bash 风格的交互式注释解析与已知工作目录，这些假定不适用于文档所面对
的 zsh 工作流。

## 复现

从仓库根目录逐行运行：

```text
cd agent
make install
make demo
```

给出任意正常的研究范围回答。第二个提示的菜单不提供决策上下文。2026-07-24 的
输入记录显示，输入可见的 `proceed: ...` 整行是自然反应；随后用户会反复收到纠正
提示，直到猜到只能输入 `proceed`。

对于 shell 文档问题，在默认交互式 zsh 中运行文档里的行内注释命令：

```text
make install # first-time dependency installation
```

它会按 `make install '#' ...` 解释并失败。

## 修复关联

这是 BUG-006 及其已完成 OpenSpec change `fix-demo-hitl2-choice-fault` 的后续。
BUG-006 在选择无效后恢复了可重试的输入校验；它没有让该决策本身变得可理解。

后续修复必须让智能体负责可从已验证状态推断的路线选择：real 模式的 HITL2 应提供
有限、已验证的决策简报、明确推荐和可解释的默认动作。只有目标读者、风险容忍度、
成本上限等真实偏好或不可逆取舍无法推断时，才向人请求决定；问题需说明所缺信息、
推荐值及各选择的实际影响。fake 模式应自动走清晰标记的 fixture 路径，或以引导方式
演示决策，而不是要求用户对不存在的研究结果进行评判。命令示例还应可在交互式 zsh
中直接粘贴且没有行内注释。修复必须保留图拥有的路由权威，也不得把全假输出声称为
研究结果。
