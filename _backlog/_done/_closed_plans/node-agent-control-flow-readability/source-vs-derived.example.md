# 已搁置的备选方案：人工内容与派生区块

> **不是 final reader interface。** 这份 discussion prototype 记录了未来若有跨节点证据时，
> checker 的最小边界；当前 final 方案不引入 metadata、generated inventory 或 checker。

## 已否决的反例

不要再建立这样的第二语义源：

```python
WORKFLOW_REVIEW = {
    "cognitive_job": {...},
    "feedback_loops": (...),
    "admission_steps": (...),
    "outcomes": (...),
    "tuning_map": (...),
}
```

即使 AST reader 能安全读取它，Coding Agent 仍要回答：谁读这个 schema、各字段怎样进入
runtime、为什么某个 label 对应某个 source symbol。大 literal 没有隐藏这些复杂度，只是把
自然语言又编码了一遍。

## 若未来重启的扩展方式

node package 只新增一份 `workflow.md`：

```text
graph/nodes/wave2_synthesis/
├── node.py
├── prompts.py
├── capabilities.py
├── capabilities/
└── workflow.md
```

人和 Coding Agent 直接维护其中的认知工作、真实 prompt assembly、feedback、authority、
symptom-to-owner map 和 worked example。第一行只保存 compact identity metadata。

可机械推导的 inventory 放进显式区块：

```markdown
<!-- BEGIN GENERATED: NODE-WORKFLOW-INVENTORY -->
... direct branches from prompt_catalog_cases() ...
... semantic edges from NORMALIZED_EDGES ...
<!-- END GENERATED: NODE-WORKFLOW-INVENTORY -->
```

## Checker 只做有界操作

拟议的 `agent/scripts/node_workflow_docs.py` 只需要两个可测试的动作：

```python
def render_inventory(logical_node: str) -> str:
    """Join code-owned prompt cases and normalized semantic edges."""


def check_workflow_doc(path: Path) -> None:
    """Validate identity, exact generated bytes, and referenced path/symbol existence."""
```

写入命令只替换 exact `BEGIN/END GENERATED` region；check 命令只读。二者都不得解释或重写
其余 prose，不导入 node factory，不调用 model/tool，不执行 graph，也不被 runtime 导入。

因此 Coding Agent 修产品问题时不需要先理解 checker。checker 只负责发现 inventory/link
漂移；`workflow.md` 才是阅读 interface。

## 事实归属

| Card 内容 | 来源 | 维护方式 |
| --- | --- | --- |
| logical node identity/classification | local metadata + `NODE_SPEC` | authored identity，checker 对齐 |
| direct branch、builder、capability ref、request tool posture | `prompt_catalog_cases()` + built `NodeExecutionRequest` | generated region |
| normalized semantic route/target | `NORMALIZED_EDGES` | generated region |
| model-visible system/request composition | capability loader + phase prompt renderer + request builder | authored exact trace + existence check |
| input/feedback/admission/outcome | node/controller/gate current implementation | authored exact refs + responsible tests |
| executable route writer/consumer/target | node/gate/builder current implementation | authored exact refs + topology/builder tests |
| symptom -> modification owner -> eval | reviewer judgment grounded in source/evidence | authored maintenance map |

## Wave2 的具体结果

机器可以稳定提供：

```text
branches:
  wave2-synthesis/repair
  wave2-synthesis/synthesis

semantic edges:
  evidence_needed -> targeted_evidence
  exhausted -> blocked
  pass -> hitl2
```

人工仍必须核对并写明：

```text
capability header is stripped; capability body enters system policy
objective + expected_output enter the user message
accepted evidence enters a delimited untrusted block
initial validation error currently triggers repair but is not sent to repair model
successful route is written by the wrapper-invoked gate
repaired invalid candidate currently propagates an exception
```

最后这几条正是 Coding Agent 决定“改 prompt、loader、validator、gate 还是 builder”所需的
因果语义。它们不能靠 branch/edge inventory 自动推断，也不应藏在另一个 Python schema 中。
