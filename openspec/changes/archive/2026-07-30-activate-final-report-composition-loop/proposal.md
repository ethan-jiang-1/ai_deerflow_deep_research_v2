## Why

Final delivery is an accepted bounded report-composition responsibility, but its real
node still formats placeholder prose deterministically. With readiness now producing
an admitted answerability plan, the report needs a constrained composition candidate
whose usefulness can be evaluated without giving a model publication or lifecycle
authority.

## What Changes

- Replace the real final-delivery formatter with one bounded, zero-tool report-composition
  Node Agent invocation that returns a typed layout candidate for deterministic report
  and claim-citation-map rendering.
- Persist the readiness-admitted report plan as a bounded immutable artifact, then
  restrict the composer to its read-only plan/evidence projection. The composer may
  choose only the order of complete approved plan entries; deterministic rendering
  injects each approved conclusion, uncertainty, and citation binding verbatim before
  the publisher writes either final artifact.
- Replace the fixture-only real final gate with deterministic final-artifact and
  accepted-evidence verification while preserving the publisher, terminal facts,
  repair/evidence-blocked routes, mixed-recipe compatibility, and full-fake behavior
  as deterministic owners.
- Add a final-delivery-local capability, prompt-catalog projection, dedicated runtime
  policy/bridge selection, exact twentieth direct-branch evidence row, and separately
  classified deterministic conformance and selected live composition evaluation.
- Update the final-delivery reader interface from accepted-but-deferred to its active
  bounded cognitive program without treating that documentation as runtime authority.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `final-delivery-node`: activate bounded report/citation-map candidate composition,
  deterministic admission, and final gate/publisher outcomes.
- `readiness-node`: persist the already admitted immutable report plan at its
  checkpointed content reference for final delivery's bounded read-only consumption.
- `node-agent-capabilities`: admit the final-delivery composer through one explicit
  local zero-tool capability and per-branch evidence row.
- `node-prompt-catalog`: include the composer's final rendered request in the
  deterministic review catalog.
- `node-agent-runtime`: bind a final-delivery-specific bounded zero-tool policy and
  bridge before model-visible work.
- `cognitive-program-evidence`: extend the exact active direct-branch ledger from
  nineteen to twenty independently reviewable rows.
- `evaluation-hardening`: distinguish scripted composition conformance from selected
  credentialed report-composition judgment evidence.

## Change Focus

- **Primary module / causal owner:**
  `agent/src/deerflow_deep_research/graph/nodes/final_delivery/`, where typed report
  candidates are composed, deterministically admitted, and handed to the existing
  publication boundary.
- **Question:** How can final delivery arrange readiness-bounded report entries into a
  useful report while preserving the plan's approved claim text and citation bindings,
  and leaving the integrity gate, publisher, and lifecycle as the only owners of
  artifacts and executable outcomes?
- **Necessary adjacent/external contracts:** `readiness` answers which conclusions,
  mandatory uncertainties, and accepted evidence may enter a composition request and
  owns persistence of that admitted plan; `publication_bundle` answers the existing
  authoritative final-artifact write boundary; a narrow `final_delivery_bundle`
  capability answers contained, integrity-checked plan/evidence and final-artifact
  reads without exposing work-unit control;
  the runtime bridge answers enforced zero-tool/budget posture; prompt capability and
  catalog contracts answer model-visible composition review; evidence registries answer
  per-branch conformance and bounded live-evaluation provenance.
- **Evidence seam:** `tests/unit/test_final_delivery_real.py` for layout admission,
  publication handoff, post-publication contained/hash-checked reads, and failures; a
  scripted real bridge case for exact prompt/policy composition; final gate/mixed-graph
  tests for routes; and a separately selected labeled composition corpus for usefulness
  judgments.
- **Not in scope:** backend or frontend changes; web/search tools; new collection or
  changes to readiness judgment/admission; citation fabrication; model-owned
  publication, checkpoint mutation, gate verdict, route, terminal status, retry, or
  graph topology; default execution of credentialed evaluation.
- **Triggered charter policies:** node-agent-workflow-integrity, workflow-outcome-review

## Impact

The change is contained under `agent/`, primarily final-delivery node code, its
capability/prompt resource, runtime resolver and prompt catalog seams, test-owned
evidence assets, and the listed OpenSpec specifications. It introduces no public API,
backend, frontend, or topology change. Credentialed model evaluation remains explicit
and supplemental to zero-API deterministic verification.
