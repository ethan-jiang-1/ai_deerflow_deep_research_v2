## Why

Deep Research can durably receive a refinement or confirmed profile note without proving that the direction reaches later cognition, while its public skill lists wire actions but does not provide a real conversational decision workflow. This change closes one deliberately small vertical loop so a user direction is classified, admitted, applied once in the same Run Bundle, consumed by a runtime-loaded topic-planning program, and evidenced at the authenticity level each claim requires.

## Change Focus

- **Primary module / causal owner:** `deep_research_harness/src/deerflow_deep_research/runtime/`, specifically the Bundle lifecycle and graph-execution boundary that owns when an admitted direction may become an applied same-Bundle refinement round.
- **Question:** How can one natural-language research direction remain distinct from a pending response, be durably admitted without silent overwrite, take effect exactly once at a declared round boundary, and reach agent-native topic planning while every lifecycle effect remains deterministic and truthfully projected?
- **Necessary adjacent/external contracts:** `domain/` defines the bounded pending/applied direction and typed lifecycle outcome; `graph/` reuses the existing full-rerun path and injects the selected Bundle/profile projection into topic planning; `agents/` answers how the existing capability loader/renderer and bridge enforce a zero-tool candidate boundary; `config/public-skill` and the dedicated Agent answer how the existing DeerFlow lead agent loads the controller workflow before classifying an ordinary follow-up and explains typed results; the effective DeerFlow configuration owns the existing `file:read` group and supplies only a preflight compatibility fact, not downstream-owned tools; `evaluation/` answers how loader, handoff, safe-point, and cognitive claims are proved without overclaiming; public `deerflow.*` skill activation and lead-agent composition answer compatibility only and require no upstream edit.
- **Evidence seam:** Bundle-local reducer and lifecycle integration tests prove no-overwrite admission, restart durability, pending-response separation, safe-point application, and same-Bundle rerun; the Phase 0 graph probe composes the production `StateGraph` topology, reducers, and rerun writer/edge with fixture adapters so it proves graph mechanics without external API calls; configuration/provisioning tests prove the unowned `file:read` prerequisite, exact dedicated-Agent materialization, and rollback boundary; real DeerFlow loader and scripted lead-agent tests prove the ordinary non-slash loading sequence and later exclusive lifecycle handoff; topic-planning renderer/bridge/materializer tests prove the real Markdown-to-candidate handoff; bounded Cognitive Evaluation cases supply supplemental controller and planning judgment evidence.
- **Not in scope:** A sixth lifecycle action; more than one pending refinement; unbounded direction history or semantic merging; migrating every node capability; changing internal phase-agent memory/subagent/todo/clarification posture; broad evidence-registry consolidation; a full-real release run; a skill-path-only file reader, a downstream-owned replacement for `file:read`, changes under `backend/` or `frontend/`; or any UI route.
- **Triggered review policies:** local-context, change-admission, authority-and-projections, participant-outcomes, human-interaction-integrity, node-agent-workflow-integrity, control-and-recovery, workflow-outcome-review, control-placement

## What Changes

- Keep `resume` and `refine` distinct. A correlated answer remains only a `resume`; a run-level direction remains only a text-bearing `refine`; ambiguous follow-up text causes clarification before any lifecycle mutation. A post-confirmation request to mutate a profile note has no hidden write path and may become `refine` only after its same-Run direction is clear.
- Replace active refinement's silent last-write-wins behavior with one bounded durable pending direction. Only the same trusted text-bearing delivery operation is idempotent through the current legal generation ceiling by a private no-text replay receipt; a different operation remains a new direction subject to the one-pending conflict rule and preserves the first direction when that slot is occupied.
- Declare a deterministic refinement-round boundary that moves the pending direction to the current round exactly once after a synchronized `COMPLETED` current round, increments the round/generation through the existing full-rerun authority, invalidates only derived projections, retains accepted evidence and prior artifacts, and re-enters `topic_planning` in the same Bundle. Stop/cancel/blocked terminal outcomes preserve but never automatically apply a pending direction; a later user-requested continuation is explicit and selected.
- Keep one public `refine` action with two strict forms. The direction form carries bounded text and is subject to trusted-operation replay/conflict rules. The continuation form omits `refinement`, requires an explicit available terminal `bundle_id` with an existing pending direction, and can only continue that existing direction. It neither submits a new direction nor writes a profile note; a missing continuation target is schema-invalid, and a nonterminal or absent-pending target is rejected without mutation. After that selected record's CAS has already committed, an explicit textless retry may only run the same already-authorized queued task when the current Bundle State/token and Bundle-contained checkpoint agree; it cannot admit, replace, or reconstruct a direction.
- Make an explicit refinement of an available ended Bundle initialize only the graph work it needs and actually start the same Bundle's next round. A terminal Bundle that already has a pending direction uses the textless continuation form rather than asking the user or Agent to reproduce hidden text. Any terminal Bundle for which no future full rerun is legal projects `start`, whether or not it retains a pending direction; a retained pending fact stays inspectable but cannot advertise a retry loop. An active suspended Bundle keeps its pending human subject; its direction waits for the next legal round boundary.
- Add bounded typed lifecycle facts whose action code distinguishes admitted/waiting, started/applied, conflict, suspended, and unavailable outcomes, while a separate Bundle refinement projection reports the selected Bundle's concurrent pending/current facts and one legal next action without exposing prompt text, operation identity, paths, or checkpoint identity.
- Read the accepted `scope_boundaries` and `custom_notes` through the selected Bundle's canonical profile reference, combine them with the applied round direction in a deterministic bounded topic-planning assignment, and keep the model candidate advisory.
- Turn topic planning into the first complete internal Markdown vertical slice: package-local capability Markdown owns the reusable decomposition/repair method and self-check; Python owns trusted data projection, schema, one-shot recovery bounds, deterministic materialization, route, and State writes.
- Expand the committed public controller skill into a focused DeerFlow workflow with decision criteria, ambiguity handling, examples, edge cases, exclusive lifecycle-call rules, and truthful typed-result handling. To deliver the requested ordinary natural-language UX, the dedicated Agent uses the existing effective `file:read` group to load the public `SKILL.md` before lifecycle selection; the preflight verifies that group and its usable `read_file` tool without creating, mutating, or misrepresenting a skill-path-only capability. SOUL keeps only stable identity and honesty posture, and the tool schema/runtime remains the action authority. The public skill does not use an `allowed-tools` workaround that would change the policy of other Agents that load it.
- Establish layered evidence for the vertical slice: actual DeerFlow skill loading, scripted real handoff, same-Bundle direction-effect workflow, and versioned bounded controller/topic-planning cognitive cases. Prewritten fake tool calls remain wiring evidence only.
- Repair the already-reproduced requirement-ID source mismatch that currently makes `make test-assets` fail, only as needed to restore the mandatory verification gate; broad metadata cleanup remains excluded.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `deep-research-harness-run-bundles`: Replaces silent refinement overwrite with a bounded pending/applied direction transition and truthful same-Bundle round outcomes.
- `research-graph-lifecycle`: Defines the durable safe-point consumption, full-rerun transition, writer ordering, and same-Bundle graph continuation for a refinement round.
- `runtime-integration`: Makes `refine` lazily start graph work when required and projects admitted/applied/conflict outcomes through the existing public tool.
- `deployment-configuration`: Makes the installed public skill and dedicated Agent express the conversational controller workflow without becoming lifecycle authority.
- `rerun-node`: Reuses the existing full-scope generation reset for an externally admitted direction in addition to the existing HITL2 rerun decision.
- `topic-planning-node`: Consumes the canonical bounded profile/direction assignment and makes runtime-loaded capability Markdown the reusable planning-method owner.

## Impact

The change touches only `deep_research_harness/`, its tests/evaluation assets, the six named capability deltas, and the minimal main-spec requirement-source declaration correction needed for the existing gate. Public action names and the opaque `bundle_id` contract remain unchanged; `refine` gains a State-gated textless continuation form without a new action or caller-supplied operation identity. Bundle-local State and lifecycle results gain bounded direction facts; Bundle graph execution gains a same-Bundle refinement entry; topic planning gains selected-Bundle profile access; public skill content grows beyond its current byte-size assertion; and the provisioned dedicated Agent gains the effective configuration's full `file:read` group, not a new path-only reader. Existing DeerFlow public APIs are consumed as-is, and no upstream service or frontend behavior changes.
