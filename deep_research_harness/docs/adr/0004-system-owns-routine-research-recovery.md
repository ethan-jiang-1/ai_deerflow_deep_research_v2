# System Owns Routine Research Recovery

Routine model, search, network, and process interruptions are System Recovery work.
The product should use bounded practical measures such as sensible timeouts, retries,
restart from recoverable Research State in an available Run Bundle, and approved
recovery paths before it involves the Primary User. When automation reaches a safety,
cost, evidence, or availability limit, the TUI presents a simple next action; technical
diagnostics remain available to the Deployment Owner and Smoke Test Operator rather
than becoming a user task.
